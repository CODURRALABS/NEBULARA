# Advanced 02 — The Bytecode VM

Nebulara's interpreter executes **bytecode** on a stack-based virtual machine.
This guide explains the concepts, informed by the `BC_*` opcodes in
`Compiler/nbs-bootstrap.c`.

---

## The three VM structures

1. **A value stack** — a list of values. Arithmetic pops inputs, pushes output.
2. **A constant pool** — strings/numbers the instructions reference.
3. **An instruction stream** — the bytecode being executed, with an
   instruction pointer (`ip`).

---

## Stack machine, concretely

Consider `PRINT 10 + 5 * 2`:

```
PUSH 10      stack: [10]
PUSH 5       stack: [10, 5]
PUSH 2       stack: [10, 5, 2]
MUL          pop 5, pop 2 -> 10 ; push 10   stack: [10, 10]
ADD          pop 10, pop 10 -> 20 ; push 20 stack: [20]
PRINT        pop 20 ; print it
```

Each arithmetic opcode pops two values, computes, and pushes one result. This
is exactly how a postfix/stack calculator works.

---

## Opcode categories you'll see

| Category | Examples | What they do |
|----------|----------|--------------|
| Push | `PUSH_INT`, `PUSH_STR`, `PUSH_BOOL` | put a literal/constant on the stack |
| Arithmetic | `ADD`, `SUB`, `MUL`, `DIV` | pop 2, push result |
| Control | `JUMP`, `JUMP_IF`, `JUMP_IFNOT` | move the instruction pointer, conditionally |
| Output | `PRINT` | pop, print |
| Calls | `CALL` | call a builtin or function by name |
| Builtins | `ABS`, `LEN` (as opcodes) | specialized operations |

Control-flow (`IF?`, `WHILE?`, `FOR!`) compiles down to **jumps**. An `IF?`
compiles roughly to: evaluate condition, `JUMP_IFNOT <skip>`, body, `<skip>:`.
A `WHILE?` compiles to a condition check + conditional jump back.

---

## Builtins vs functions

- **Builtins** (like `ABS`, `LEN`) are dispatched inside the VM by name.
- **User functions** (`FUNC!`) get their own call frame on the stack.
- `TYPEOF` reveals the runtime type; arrays are heap-allocated value arrays.

---

## The `.nbsc` format

`neb-cli build file.nbs` serializes the compiled program to bytecode
(`.nbsc`). This is the "compiled" artifact the VM can run without re-parsing
the source. (The v4 spec extends `.nbsc` to embed an IR section so it can be
**decompiled** without source — part of the "no dark binaries" goal.)

---

## Reading the interpreter source

In `Compiler/nbs-bootstrap.c`, find the main execution `switch`. Each case is
one opcode. Cases like `BC_PRINT` and `BC_CALL` are great starting points to
see:
- how the stack pointer (`sp`) advances,
- how the instruction pointer (`ip`) reads operands,
- how builtins are resolved by name.

---

## Determinism note

The VM is deterministic except for `RANDOM()`, `TIME()`, and FFI calls. This
matters for reproducible executions (and for the PRIMORDIA project's
checkpoint/replay ambitions).
